# 采集间隔输入校验修复设计

## 背景

新建或编辑采集站时，采集间隔输入 `600` 会被浏览器判定为无效，表单无法提交。后端 `collectionSiteSchema` 已将该字段定义为正整数，并能正常接受 `600`。

## 根本原因

前端通用 `NumberInput` 同时设置了 `min="0.0001"` 和默认 `step="1"`。数字输入的步进基准由 `min` 决定，因此浏览器只接受 `0.0001 + n`，整数 `600` 会触发原生 `stepMismatch`。

## 预期行为

- 采集间隔单位为秒。
- 采集间隔必须是大于或等于 `1` 的整数。
- `1`、`60`、`600` 等整数可以通过浏览器原生校验并提交。
- 小于 `1` 的值和小数继续被前端或后端明确拒绝。
- 充值倍率继续支持大于 `0` 的小数。

## 设计

扩展 `NumberInput` 的属性，使调用方显式传入字段自身的最小值：

- 采集间隔使用 `min="1"`、`step="1"`。
- 充值倍率使用 `min="0.0001"`、`step="any"`。

不修改后端校验、数据结构或采集调度逻辑。该修复只纠正前端 HTML 约束与既有业务规则不一致的问题。

## 测试

先增加一个失败的 UI 结构回归测试，断言采集间隔输入具有 `min="1"` 和整数步进，同时充值倍率仍允许小数。确认测试因当前 `min="0.0001"` 的共享实现而失败后，再实施最小组件修改。

完成后运行：

- 定向 UI 测试。
- 完整测试套件。
- TypeScript 类型检查。

## 范围

仅修改 `s2a-rate-bot` 的采集站表单及对应测试，不包含其他表单重构或采集周期策略变更。
